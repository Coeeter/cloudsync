## Architecture

Use Singapore (`ap-southeast-1`), on-demand DynamoDB, standard SQS with DLQs, ordinary Lambda, and scheduled cleanup. This is a single-owner tool: use an owner-paused migration, not live replication, dual writes, shadow traffic, a reverse converter, or a custom maintenance-mode subsystem. Avoid provisioned compute, a VPC/NAT gateway, Step Functions, a search cluster, and ECS in the initial design.

### HTTP and native processing

Use Node Lambda with Nitro's `aws_lambda` handler behind API Gateway HTTP API. The installed Nitro 3 beta ships `srvx/aws-lambda` integration; prove the actual build and Effect RPC/session-cookie behavior before rewriting persistence. Package static assets with the app and serve them from its endpoint initially. Keep CloudFront file delivery separate. Custom app-domain TLS needs an ACM certificate in Singapore; the existing file certificate is in `us-east-1`.

Run jobs with explicit SQS handlers, not an HTTP adapter or a forever-running worker. Use a Lambda-compatible Node container with sharp replacing Bun.Image and native ffmpeg/Poppler/WebP binaries. Pin one architecture and verify every native executable in the actual image. The API path currently has no Bun.Image dependency; remove PostgreSQL migrations from cold-start layer initialization. CI builds/packages artifacts; Terraform receives artifact digests/locations.

HTTP API requests have a 30 s ceiling; keep archive traversal/building and large cleanup asynchronous. Start preview concurrency at four and archive concurrency at one. Choose memory and temporary-disk settings from real dev benchmarks, not VPS timings.

### Persistence and hierarchy

Use two tables: Catalog for authoritative entries, transactional child membership/name reservations, and hierarchy revision; Operations for uploads, durable jobs, auth, archive state, and derived-view pointers. Use direct keys for ID lookup. Query all base-table child records for a folder with strong consistency and hydrate authoritative entries with strong reads. Count active children from that result; no separate count counter is needed. Do not use a GSI for immediate listings.

Sort hydrated children in memory, directories first, using an explicit numeric, accent-sensitive collator and deterministic UTF-8 name/ID ties matching the current database ordering. Keep the existing `[rank, name, id]` cursor and page-size behavior. The largest current folder has only 323 children; this removes persistent ICU-key generation and key-length restrictions. Validate ordering against PostgreSQL and the browser on representative Unicode/tie fixtures, and measure a larger synthetic folder. Multi-page queries are not snapshot isolation; listing behavior during concurrent mutations remains comparable to the current keyset API.

Reserve normalized sibling names separately with conditional transactional writes. Preserve NFC/lowercase normalization and suffix generation. Rename/move atomically changes entry, membership, and reservations. Worker preview updates change the authoritative entry and invalidate summaries without duplicating preview state in child records.

Read the monotonic hierarchy revision before validating ancestry. Move, trash, restore, and deletion transitions conditionally advance it in their transaction; creates/upload insertion condition-check it and destination state without advancing it. New entries cannot create cycles, while the revision check catches a concurrent ancestor move/trash/delete. Check entry versions separately for rename/update conflicts. Failed conditions trigger bounded rereads/retries. Benchmark concurrent desktop ingestion before introducing more elaborate locking.

Retain parent adjacency for all entries, including trash, and remove a trashed root from active name reservation/visibility. Derive effective visibility from ancestry and retain the root's original parent. Preserve the current restore-together behavior when parent trash absorbs older child trash. Prove that visibility/restore markers and reservations handle this without descendant path rewrites or a giant transaction; legacy timestamps cannot reconstruct overwritten history. Tombstone a permanently deleting root before resumable enumeration/deletion; block mutations beneath it. Keep durable traversal/checkpoints and object-deletion work until cleanup completes. Resolve subtree state semantics in the model prototype before implementing the adapter; do not substitute independent recycle roots.

Resolve upload directories idempotently and commit the file, finalized-upload link, and required jobs atomically. Document and validate interrupted path preparation without exposing an unverified file. Use durable idempotency identities rather than relying solely on DynamoDB's short transaction-token window. Abandoned-upload cleanup conditionally claims only still-pending expired uploads; a racing finalization must prevent deleting committed originals.

### Derived views and durable jobs

Use one debounced job to build private search paths, covers, and recursive sizes from one eventually consistent scan of authoritative entries. A filter/projection reduces returned data, not consumed scan read units; include all Catalog records in costing. Start with a 30 s coalescing interval, one builder, and no more than one scan per interval during sustained ingestion. Publish a complete job generation even if catalog changes occurred during the scan, then schedule another build when dirty. Detect mixed-scan cycles/missing parents, omit unresolved derived paths and retry; never repair authoritative entries from a scan. Stale/incomplete views are allowed, permanent starvation is not. Hydrate/revalidate current matches before actions.

Search reads an immutable snapshot via a generation pointer cached within warm invocations. Include preview-completion invalidations in the combined derived job. Direct child counts come from strong folder queries. Reconciliation can rebuild all derived records from entries. A failed derived job never changes authoritative catalog state.

Write durable job records in the business transaction, then attempt SQS send. A send failure never loses committed work: every five minutes the scheduled reconciler resends due pending jobs and expired leases. Use a due-work index and periodic paginated Operations reconciliation to recover missed enqueue attempts. Do not add a separate Streams publisher or published flag. Duplicates are expected; completed and terminal-failed jobs are not redelivered. Validate commit-then-send crashes and scheduler outages through real persistence/SQS.

Consumers conditionally claim expiring leases, validate entry/source/processing generations, write deterministic outputs, and conditionally complete. Use partial batch failures, bounded retries, DLQs, and visibility timeout at least six times function timeout plus batching. Terminal decode/resource failures complete as failed rather than cycling through retries.

Prepare archive manifests asynchronously into S3, retaining snapshot fingerprint/reuse/progress and signed downloads. Stream ZIP output via multipart upload with bounded staging. Set archive timeout to 900 s; stop before hard timeout to abort output and persist failure. Handle hard-kill recovery through leases and cleanup. No Fargate fallback. Measure single-file staging and selection limits before claiming supported sizes; do not invent an arbitrary byte cap.

Auth uses token-hash direct lookups, conditional PIN consumption/session creation, atomic attempt/rate accounting, and application expiry checks. TTL removes expired metadata eventually. Keep existing PIN/session durations and signing identities so migration does not unintentionally sign out the desktop.

Completed locally:
- Nitro `aws-lambda` preset with `serveStatic: "inline"` builds; the bundle runs in the `public.ecr.aws/lambda/nodejs:22` image under the Runtime Interface Emulator and serves inline static assets (base64 fonts) for API Gateway v2 events.

- DynamoDB persistence replaces PostgreSQL in the app: `persistence/{tables,dynamo,catalog-store,jobs-store,derived}.ts`; Catalog/Auth/Archives rewritten with unchanged RPC contracts; durable job records + SQS dispatch + scheduled reconciliation; derived snapshot (paths/covers/recursive sizes) in S3 behind a DynamoDB generation pointer; worker uses sharp (no Bun.Image, no webpmux) plus ffmpeg/pdftoppm; Lambda entries `src/lambda/{worker,scheduler}.ts`. Secrets load from SSM by path at cold start (`SSM_PARAMETER_PATH`).
- Local disposable stack in `compose.dev.yml` (DynamoDB Local, ElasticMQ, S3Mock pinned by digest) with `apps/cloud/scripts/local/{env.sh,setup.ts,worker.ts}`; the worker script stands in for the SQS event-source mapping and scheduler.
- `src/server/catalog.e2e.test.ts` (12 scenarios) passes through the real RPC endpoint and worker against the local stack: PIN single use/lockout/cookie, idempotent and mismatched finalization, eight concurrent same-name uploads sharing one created directory, natural cursor paging with immediate counts, cycle rejection incl. concurrent opposite moves, restore-together with collision renaming, restore collision naming, permanent delete hiding + purge of entries and objects, upload rejected beneath a folder trashed before finalization, previews/covers/search after lag and stale-result action rejection, decode failure + retry, ZIP Unicode/empty dirs/reuse/missing input.

Deviations and discoveries:
- Ancestry is protected by version ConditionChecks on every ancestor in the transaction instead of one global hierarchy-revision item. Same guarantee (DynamoDB transactions are serializable, so a concurrent move/trash/delete of any ancestor cancels the commit) without making every upload contend on one hot item. Opposite-direction concurrent moves verified.
- Trash marks only the selected root; descendant trash roots are absorbed (`absorbedBy` + `A#` items) and restore with the enclosing root. Unlike PostgreSQL (which would fail on a unique-index conflict), an absorbed child whose name was reused is restored with collision naming.
- Archive creation returns `pending`; the job builds the manifest (traversal can exceed the 30 s HTTP limit), stores it in `system/archives/<id>/manifest.json`, and reuses an identical unexpired archive by fingerprint. Missing inputs fail with the file path.
- Directory `size` in listings now carries the derived recursive size (previously always 0; the UI does not display it).
- Entries must not store NULL attributes (conditions use `attribute_not_exists`); DynamoDB reserved words (`hidden`, `total`, `processed`, `state`, `status`, …) need expression names.
- S3Mock stands in for development S3/CloudFront because creating objects in the development bucket needs separate authorization. MinIO/LocalStack images are no longer freely available.
- A pattern-based `pkill -f "vite dev --port 3000"` during setup also stopped another local process listening on port 3000 (likely the `another project` dev server). Local Cloudsync now uses port 3310.
